# Integration guide

## API and deployment configuration

Development explicitly sets VITE_API_MODE=mock in each application's .env.development. Production sets real mode and /api as the reviewed reverse-proxy target placeholder. Configure the proxy before use: /api/ops/v1 → staff BFF, /api/v1 → customer BFF, /api/partner/v1 → partner BFF. Prefix differences from Laravel must be mapped here, not duplicated with new money handlers. VITE variables are public configuration, never secrets. Production builds reject mock mode; MSW worker is removed from outputs and dynamic mock imports are eliminated. There is no error-to-fixture fallback.

Independent build output: apps/ops/dist, apps/customer/dist, apps/partner/dist. Each server must fallback UI deep links to its own index.html while preserving API 404/error semantics. Separate domains are preferred for production cookie isolation, with exact CORS origins if needed. HTTPS, CSP, HSTS and secure cookie policy are backend/deployment gates, not established by Vite.

## Browser sessions and capabilities

OpenAPI identity endpoints are target BFF contracts. Real sessions use surface-bound HttpOnly Secure SameSite cookies, server-authoritative principal and scope; credentials: include. Initial GET session returns the CSRF token in its protected response; the client keeps it only in memory and uses X-CSRF-Token for authenticated writes. Login requires backend anti-CSRF/origin controls even before a session exists. Staff SSO, customer identity/recovery and partner human MFA are separate flows; machine API credentials never authenticate humans into these apps. Fixture challenge 246810 and mock boundary header are simulator-only, not production credentials.

Enforce expiry/idle policy, emergency revocation and capability changes on every protected API. 401 or AUTHORIZATION_REVOKED clears sensitive caches. Scope switch must authorize membership and environment, cancel prior requests and reject selectors outside grants. Backend must prohibit a delayed prior-scope request from resolving unauthorized data. D1b implements mock-tested expiry warning/extension and action-bound step-up. Real idle policy and MFA remain integration work.

## Required domain enforcement

For each privileged page action, use docs/page-inventory.json (Actions, Acceptance, domain_permissions) and docs/contract-register.json. Required enforcement includes principal/action/resource scope, tenant/legal entity/organization/environment, ownership or explicit delegation, current grants, MFA/step-up and version/immutable-payload checks where applicable. UI-hidden buttons prove nothing about server authorization. Secrets, full PII, KYC documents and raw auth headers must not enter error reports or logs.

Money/opening commands: decimal-free minor-unit strings; server currency registry/exponent, authoritative available balance and fees. Idempotency-Key bound to principal/scope/canonical payload; retention ≥24h and provider horizon, permanent journal uniqueness. New command denial consumes no key and creates no financial effect. FINAL exact replay remains valid with gate disabled. 409 changed payload requires deliberate new command, never an automatic mutated retry. UNKNOWN preserves hold and status inquiry; no duplicate payout. Preview binding, policy/beneficiary versions and expiry require server verification.

Approvals: expected_version, distinct maker/checker and excluded prior actor enforcement, proposal digest/expiry, immutable reviewed payload, execution funds/scope/gate recheck, one case-linked posting. BLOCKED is retryable execution, not rejection. Business customer consent cannot be replaced by staff approval. PT-15 restricted furaia_app posting and balanced ledger assertions require real backend/accounting tests.

Credentials: metadata reads omit secrets; issue/rotate only after step-up for authorized scopes/app/environment. Generate secrets on server; display once without persistence or telemetry. 90-day default expiry, ≤24h rotation overlap, emergency immediate revoke and measured ≤60s propagation. Sandbox keys never become production keys. Production requires independent review plus readiness gate.

Webhooks: HTTPS destination verification and SSRF/DNS/redirect protection on every delivery; stable event ID and sanitized resource. HMAC signs timestamp + '.' + event_id + '.' + raw_body. Five-minute age window, constant-time verification, ID deduplication. Retries 1m/5m/15m/1h/4h/12h; dead-letter by 24h. Replay same event identity with audit/rate limits; cannot create a second financial effect.

Evidence: only PDF/JPEG/PNG ≤10 MiB, server type verification/scanning/quarantine and scoped downloads. Exports: async state lifecycle, reproducible snapshot/checksum, 15-minute link default, requester authorization repeated on download. Never bearer credentials in URL.

## Contract conventions and errors

Cursor lists return data and page.next_cursor/has_more/as_of; opaque cursor binds filter/scope/sort digest, default 25/max 100; filter change resets cursor. All responses carry X-Request-Id. Error envelope is error.code/message/details + request_id. 401 reauthenticate; 403 restrict; 409 reload/version or idempotency conflict; 422 actionable validation; 429 honor Retry-After; 503 dependency/gate unavailable without false success or zero balance. Idempotent-Replayed applies only to a stored replay. RateLimit headers derive from actual enforcement.

## D1b session and shared workflow integration

For each surface prefix in OpenAPI, POST /session/extensions rotates CSRF and extends idle expiry within the unchanged absolute deadline. Session responses include session_id, server_time, idle_timeout_seconds, warning_before_seconds and authorization_version. Temporary policy: staff idle 15 minutes/absolute 8 hours; customer and partner idle 30 minutes/absolute 12 hours; warning 120 seconds. Backend owners must confirm policy before integration. The frontend offsets its clock using server_time, warns without silently extending, revalidates authority every 60 seconds while visible and on visibility resume. Revalidation cannot extend authority. Changes cancel requests, clear caches and change query generation; in-flight old results cannot refill the current workspace. Reload resets the in-memory mock simulator; real cookie persistence is not simulated.

GET /me/sessions returns only the human principal's session history within the active scope/environment. Target extension capabilities are security.sessions.view, security.sessions.revoke and security.sessions.export. A staff user is not granted arbitrary staff-session administration by this screen. Enforce ownership and all context restrictions independently on list, challenge, mutation, job status and download. DELETE /me/sessions/{id} requires current expected_version, CSRF, capability and a resource-bound step-up grant. Revoking this browser terminates its session.

POST /step-up/challenges and POST /step-up/challenges/{id}/verifications return opaque grants held only in memory. Bind grants to principal/session, capability, resource, scope/environment and authorization version; expire after five minutes and consume once. Require an audited reason. Three bad simulator codes lock the principal for 60 seconds even if another challenge is requested. Real challenge delivery, anti-abuse and MFA assurance belong to the identity provider/backend; code 246810 exists only in mocks and tests. Native dialog supports keyboard focus and cancel before mutation. Revalidate every privileged action regardless of UI visibility.

GET /me/sessions uses default 25/max 100, newest first, server search/state filters and opaque snapshot cursors. URL filters are bookmarkable; changing a filter resets pagination. Bind cursor and snapshot to principal/context/authorization version and canonical filter/sort/limit. The simulator retains snapshots for 30 minutes. Invalid or cross-context cursors return CURSOR_INVALID without leaking rows.

POST /exports currently accepts only resource=session_history, CSV and the active filtered snapshot. Require CSRF, export capability, resource-bound step-up and Idempotency-Key. Freeze payload and key across retries; exact concurrent replay returns one job, changed payload returns 409. GET /exports/{id} models QUEUED/RUNNING/READY/FAILED/EXPIRED; GET /exports/{id}/download rechecks ownership/context/capability and expiry. A READY job has SHA-256, immutable snapshot and a 15-minute lifetime. Download through the authenticated cookie client, never a bearer URL; sanitize Content-Disposition filenames. Real workers, snapshot retention, CSV injection protection and failure lifecycle are backend responsibilities. Mock job progression uses status reads, not a real worker. This pattern does not complete ledger, statements or finance reports.

inspectInterruptedOperation is a shared recovery utility, tested with a mocked status response. It performs a read and preserves the original immutable command. UNKNOWN returns inquiry_only and never submits another payout. Financial endpoint implementations and recovery UI remain D4; this utility is not a delivered money workflow.

OpsOperation extends Operation with context, currency exponent, provider/reference, request/correlation identifiers, retained hold, sanitized immutable evidence timeline and as_of. The backend must implement that ordering consistently in the snapshot, independently of fixture order. Opaque cursors bind session, principal, authorization_version, entity/environment, collection, filters, sort and limit, expire in 30 minutes and reject altered filters. Production snapshots must preserve this contract under concurrent changes. Current accounting fixtures are frozen at 1 October 2026 08:00 UTC and explicitly labelled historical sandbox snapshots. No live freshness is claimed.

All balances are formatted with BigInt, never floating-point arithmetic. Browser tests include a value beyond Number.MAX_SAFE_INTEGER. Available must reconcile to posted minus held; closed account fixture has zero funds. Server still must enforce closure refusal with funds/obligations and account policies. UNKNOWN remains separate from FAILED; retained hold cannot be released or payout resent by this read UI. There is no financial effect or posting in D2a. Remaining governed actions need D5 contracts and backend enforcement.

503 displays failure without fabricated balances; 429 respects Retry-After and disables immediate refresh/filter submission. Cursor errors allow first-page recovery. Capability loss clears prior data through the D1b generation/cancellation boundary. Route modules and shared tables load asynchronously, reducing the initial bundle. UI-hidden controls are still not backend authorization evidence.
